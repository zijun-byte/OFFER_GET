# 手机版简历流程（2026-10-24）

## 界面与数据

- 760px 及以下使用全屏手机工作区，沿用薄荷纸页设计令牌。助手气泡左对齐并显示 Offer GET，用户气泡右对齐且无姓名标签；用户消息超过四行可展开。顶部品牌复用首页字体。
- 作品集独立为第 3 题，只有该题显示跳过；其他题没有相关经历可回答“暂无”。旧草稿按步骤迁移，已完成的问答不重开。
- 编辑阶段发送的指令、追问、成功/失败、待确认、取消与撤销写入同一份本地对话记录。附件仅记录文件名，不保存原附件。
- 手机纸面取消固定比例限制，随长内容增长；打印规则独立保留。键盘打开时隐藏保存状态并缩小底部间距；浏览器原生工具条仍由浏览器控制。
- 问答结束前不展示实时预览。完成后以同一份 `ResumeData` 展示简历，底部输入框保留；右上角可看问答记录及调用浏览器打印/保存 PDF。
- 点击简历模块打开字段编辑面板，不使用 `contentEditable` 改整张纸。教育列表可编辑多条。
- 输入框自动增高并支持展开；通过 Visual Viewport 跟随软键盘。模板选择、粘贴简历和附件入口在输入框工具栏。
- 桌面与手机共用 intake/extract/edit/attachment 接口和数据结构。草稿仍保存在当前浏览器，**不是跨设备云同步**。

## 修改保护

- `/api/resume/edit` 复用后台 `resume-extractor` 的模型、供应商与启用设置，但使用独立的修改协议。模型返回 `set/add/remove`，已有条目通过固定 ID 定位。
- 服务端和客户端共用字段白名单及值类型校验；禁止任意对象路径、修改 ID 和未知模块。模型返回追问时不执行操作。
- 普通小修改直接应用；删除、清空、数组替换或超过五项修改先展示前后对比，确认后应用。
- 应用前比较简历快照，处理中有手动修改则拒绝旧结果。重复点击由请求锁阻止；相同新增条目不重复追加。
- 保留最近一次 AI 修改/导入的撤销快照（当前会话）。之后发生其他编辑时，不用整份旧快照覆盖新内容。
- 失败/超时保留输入，不伪报成功。问答回答、当前进度和输入草稿保存在本地；保存失败显示提示。
- 原始附件只在内存中处理，不写入磁盘；刷新可能丢失未确认附件，页面离开时尝试给出浏览器提醒（手机浏览器可能不显示此提醒）。

## 附件与成本

- 最大 8MB。TXT、DOCX、文字版 PDF 在服务器本地提取正文，不需要模型调用；PDF 最多 12 页，提取文字最多 40000 字。
- DOCX 仅读取正文 XML，限制解压体积，拒绝实体定义。不支持旧版 `.doc`、加密/损坏文件；扫描版 PDF 提示转图片或粘贴文字。
- 文件先识别为文字，用户核对后再调用已有文字模型提取字段；最终替换前再次确认，模板不变。
- PNG/JPG/WebP 走可选视觉模型。配置 `RESUME_VISION_MODEL`、`RESUME_VISION_PROVIDER`（默认 openai）及对应 OPENAI/AI 服务凭据。**未配置时明确拒绝图片识别，不自动换用付费服务。** 上传前会提示处理用途。
- 不自动重试付费模型。修改请求复用原文字模型；取消操作、模板切换、手动编辑、撤销均不调用模型。
- PDF 解析使用 [unpdf 官方接口](https://github.com/unjs/unpdf)，逐页读取并释放加载任务。
